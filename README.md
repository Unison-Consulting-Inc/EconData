# EconData

Published economic indicator parquets for US nation / state / metro-area geographies. Every
file here is a small, tidy, analysis-ready extract built from public federal statistical
releases (BLS, BEA, Census) by the `econ-download` pipeline; the raw source downloads are
never committed here, only the cleaned outputs.

**This is a PUBLIC repo and it must stay public.** Its consumers fetch the parquets over
anonymous `https://raw.githubusercontent.com/.../master/<file>.parquet` URLs — including a
browser-based dashboard that reads them directly with DuckDB-WASM, with no server, no
credentials, and no build step in between. Two consequences follow, and both are load-bearing:

1. **Do not make this repo private.** Every raw URL would start returning 404 and every
   consumer would break instantly.
2. **Never enable Git LFS here.** `raw.githubusercontent.com` serves the LFS *pointer stub*
   (a ~130-byte text file) instead of the real object. DuckDB-WASM and `pandas.read_parquet`
   would both fail on it. There is no `.gitattributes` in this repo today; keep it that way,
   and keep `*.parquet` un-ignored in `.gitignore` (the file carries an explicit note saying
   so).

## Datasets

Seven parquets. All seven share the same shape for the analytic files: one row per
`area` x `year`, with `type` identifying the geography level (`nation`, `state`, `msa`),
a `date` column set to the period end, and a `latest_date` column carrying the most recent
observation date present in the underlying source series.

| File | What it is | Source | Grain / coverage | Regenerated by | Cadence |
|---|---|---|---|---|---|
| `bea.parquet` | Population, real GDP, real personal income, and their per-capita forms | BEA Regional accounts — tables `SAGDP`, `SAINC` (state), `CAGDP1`, `CAINC1` (county/MSA), downloaded as ZIPs from `apps.bea.gov/regional/zip` (`pipeline.py:337-362`) | area x year; `nation`/`state`/`msa`; 2001–2025; 10,516 rows | `econ-download/clean_data.py:1144` | Quarterly (`--bea` runs) |
| `ces.parquet` | Nonfarm payroll employment by supersector | BLS Current Employment Statistics — national `ce.data.0.AllCESSeries` and State & Metro Area `sm.data.1.AllData` flat files from `download.bls.gov` (`pipeline.py:136-137`) | area x supersector x year; `state`/`msa`; 2000–2026; 118,501 rows | `econ-download/clean_data.py:1137` | Monthly |
| `lau.parquet` | Labor force, employment, unemployment level and unemployment rate | BLS Local Area Unemployment Statistics — `la.data.3.AllStatesS` (state), `la.data.64.County` (county), national from `ln.data.1.AllData`, plus the seasonally-adjusted MSA table `bls.gov/web/metro/ssamatab1.txt` (`pipeline.py:133-135,182`) | area x year; `nation`/`state`/`msa`; 1990–2026; 12,363 rows | `econ-download/clean_data.py:1128` | Monthly |
| `pop.parquet` | Resident population | Census Bureau Population Estimates Program (PEP) county totals: `co-est00int-tot.csv` (2000–2010 intercensal), `co-est2020.csv` (2010–2020), `co-est2025-alldata.csv` (2020–2025, with a 2024 fallback) from `www2.census.gov/programs-surveys/popest` (`pipeline.py:622-633`) | area x year; `nation`/`state`/`msa`; 2000–2025; 25,220 rows | `econ-download/clean_data.py:1121` | Quarterly (`--census` runs) |
| `qcew.parquet` | Establishment counts | BLS Quarterly Census of Employment and Wages (QCEW) — `data.bls.gov/cew/data/files/{year}/xls/{year}_all_county_high_level.zip` (`pipeline.py:286`) | area x year; `nation`/`state`/`msa`; 2001–2025; 10,817 rows | `econ-download/clean_data.py:1166` | Quarterly (`--qcew` runs) |
| `rpp.parquet` | Regional Price Parities: all items, goods, housing/rent, other services, utilities | BEA Regional API — tables `SARPP` (state) and `MARPP` (MSA) via `apps.bea.gov/api/data`, requires a BEA API key (`pipeline.py:510-533`) | area x year; `nation`/`state`/`msa`; 2008–2024; 7,463 rows | `econ-download/clean_data.py:1149` | Quarterly (`--bea` runs) |
| `census_geocodes.parquet` | FIPS-code lookup table: `FIPS`, `Name`, `Type` for US / State / County / MSA / µSA / Minor Civil Division / Incorporated Place / Consolidated City | Census geography references: the vendored `all-geocodes-v2022.xlsx` workbook + the CBSA gazetteer, assembled by `econ-download/census_geocodes_build.py` (added 2026-08-10; v2 published 2026-08-11 with corrected type labels and unique sub-county FIPS) | 44,745 rows; static, no time dimension | `econ-download/census_geocodes_build.py` (has a `--check` verification mode) | On demand — static reference; regenerate only deliberately |

Two non-data files are also tracked:

- `.gitignore` — ignores CSV/XLSX inputs and `cbsa_types.json`, and deliberately does **not**
  ignore `*.parquet` (see the comment in the file).
- `requirements.txt` — the pipeline's Python dependencies (pandas, pyarrow, numpy,
  requests). It documents what `econ-download` needs; nothing in this repo executes.
  It deliberately lists no object-store client: publishing is a git push to this repo,
  not an upload. A `boto3 >= 1.34.0` entry for "optional R2 upload" was removed on
  2026-08-06 — it was never used by any code, and it repeatedly led readers to believe
  Cloudflare R2 was part of the architecture.

## Consumers

| Consumer | Repo / file | Datasets used | Fetch type |
|---|---|---|---|
| Econ dashboard | `dash/econ` — `src/lib/duckdb.ts:11-20`, registered as DuckDB views at `duckdb.ts:83-101` | `pop`, `lau`, `ces`, `bea`, `qcew`, `census_geocodes` (6 of 7 — **not** `rpp`) | **Browser.** DuckDB-WASM in the user's browser issues anonymous HTTP range requests against the raw URL; base URL is overridable with the `VITE_DATA_URL` env var |
| Traffic-forecasts report engine | `unison/traffic-forecasts/report-engine` — `src/econ_data.py:29-38`; also read via `src/econ_acs.py:178-179` and `src/econ_geography.py:201-203` | All 7, including `rpp` and `census_geocodes` | **Server-side.** `requests.get(...)` streams each raw URL into a temp cache (`econ_data.py:83-88`), then `pandas.read_parquet` (`econ_data.py:100`) |

Notes on the two consumers:

- The dashboard *registers* `census_geocodes` as a view at `duckdb.ts:99`, but no hook or page
  issues SQL against it — `src/hooks/useData.ts` queries only `population`, `lau`, `bea`,
  `qcew`, `ces`. The registration still touches the file at init, so the file must exist.
- The report engine prefers a local copy when one is present: if
  `SHARED_ECON_BASE/<dataset>.parquet` exists (`report-engine/config.py:44`, which resolves to
  the same Dropbox directory the pipeline writes into) the HTTP fetch is skipped entirely
  (`econ_data.py:74-77`). On a machine without that Dropbox folder it falls back to the raw URL.

No other known consumer reads these files outside of test fixtures
(`traffic-forecasts/report-engine/tests/test_econ_data.py`,
`econ-download/tests/test_data.py`), which use synthetic parquets and never hit the network.

## How the data is refreshed

The producing pipeline is **`econ-download`**
(`github.com/Unison-Consulting-Inc/econ-download`, **private** — org membership
required). Its `pipeline.py` downloads
raw sources into Dropbox, `clean_data.py` writes the six generated parquets into a local
checkout of this repo, and the checkout is committed and pushed. Read
`econ-download/RUNBOOK.md` before running anything by hand.

**Automated path — GitHub Actions `econ-refresh.yml`** (`econ-download/.github/workflows/econ-refresh.yml`):

| Cron (UTC) | Mode | What it refreshes |
|---|---|---|
| `0 17 20 * *` | monthly | BLS only — `lau`, `ces` |
| `0 17 31 3 *` | quarterly | QCEW Q3 + Census county PEP |
| `0 17 30 6 *` | quarterly | QCEW Q4 + BEA state Q1 |
| `0 17 30 9 *` | quarterly | QCEW Q1 + BEA annual state revision |
| `0 17 30 12 *` | quarterly | QCEW Q2 + BEA RPP + BEA county annual |
| `0 17 12 2 *` | quarterly | Catch-up for BEA county annual when it slips Dec to Feb |

The workflow picks monthly vs quarterly from the calendar date and fails loudly on an
unexpected date rather than guessing. `workflow_dispatch` accepts an explicit
`mode` input (`monthly` or `quarterly`). Quarterly runs invoke
`pipeline.py --qcew --bea --census`; monthly runs invoke `pipeline.py` with no source flags.
Secrets required: `ECONDATA_PUSH_TOKEN`, `BEA_API_KEY`, `FRED_API_KEY`.

**Legacy path — launchd on the maintainer's Mac.** `com.econdata.monthly-update.plist`
(day 20, 09:00 America/Los_Angeles) and `com.econdata.quarterly-update.plist` (Mar 31,
Jun 30, Sep 30, Dec 30, Feb 12 at 09:00) are symlinked into `~/Library/LaunchAgents/`. The
Actions crons above are a UTC translation of these, computed against a fixed UTC-8 anchor, so
during PDT the workflow actually fires one hour later than the plists' nominal 09:00 wall
clock.

**Manual run**, from an `econ-download` checkout, with this repo cloned to the path
`clean_data.OUTPUT_DIR` points at (hard-coded in `clean_data.py:59` to a macOS
Dropbox location; see `econ-download/RUNBOOK.md` for what that means on CI and
other machines):

```
# monthly (BLS only)
python3 pipeline.py --no-publish

# quarterly (adds QCEW + BEA + Census)
python3 pipeline.py --qcew --bea --census --no-publish

# then, from this repo's checkout:
git add -- '*.parquet'
git commit -m "Update data: <sources> <Mon YYYY>"
git push origin master
```

Dropping `--no-publish` lets `pipeline.py:publish_to_github()` (`pipeline.py:800-855`) do the
`git add`/`commit`/`push origin master` itself.

There is no build or deploy step downstream. Pushing new parquets to `master` is what makes
fresh data visible — the dashboard picks them up on the next page load.

## Caveats

### `census_geocodes.parquet` is not written by the scheduled pipeline

`clean_data.py` writes exactly six parquets and `census_geocodes` is not among them —
scheduled refreshes never touch it. It has its own dedicated generator,
**`census_geocodes_build.py`** in the `econ-download` repo (added 2026-08-10, with a
`--check` mode that verifies a fresh build against this published file; source
workbooks vendored beside it). If the file is ever deleted or corrupted, rebuild it
with that script — do not hand-edit or re-derive it ad hoc. It was accidentally
untracked once in this repo's history and had to be restored, so treat it with care:
44,745 rows, `Type` values `US / State / County / MSA / μSA` plus sub-county rows.

### Where refreshes come from

This repo is the publish target of `econ-refresh` (GitHub Actions in
`Unison-Consulting-Inc/econ-download`): scheduled runs clone this repo, write the six
generated parquets, and push. The deployed econ dashboard reads this repo's raw URLs
at page load, so a push here is immediately live.

### The pipeline code is private

`econ-download` is a **private** org repo — anyone refreshing this data needs org
membership (and the Actions secrets listed above for CI, or the RUNBOOK's manual
path).

### `rpp.parquet` has one consumer, not two

The econ dashboard does not read `rpp.parquet`. Only the traffic-forecasts report engine does.
Do not assume dashboard behavior tells you whether RPP is still needed.

### Coverage end-dates differ per file

`rpp` ends at 2024, `bea`/`pop`/`qcew` at 2025, and `lau`/`ces` at 2026. This is normal — it
reflects each agency's own release lag, not a broken pipeline. Use the `latest_date` column
inside each file to see how current the underlying source series is.
